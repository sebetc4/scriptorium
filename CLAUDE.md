# scriptorium

A library of documents written in Markdown and built to paginated PDF and
reflowable EPUB. One directory under `library/` = one document (`index.md`);
the directories above it are topics, at any depth. `library/` is user content:
never reorganise or translate it unasked.

## Which skill

Every job has a skill that carries its rules. Open it before acting.

| Intent | Skill |
|---|---|
| Write, build, review a PDF document; art direction, icons, diagrams; import an external PDF into the library | `pdf` |
| The EPUB output, its contact sheet and style proof | `epub` |
| Capture one known web page as a document | `fetch` |
| Investigate a question across unknown sources — produces knowledge, not a document | `sourcing` |
| Translate a document already in the library | `translate` |
| Review a finished task — what it cost and what should change | `session-review` |

The last is outside the production chain: it makes no document and
changes no skill. It runs once a task is done, never during one.

## Repo map

| Path | Role |
|---|---|
| `core/` | Installable package shared by the skills: `doc` (discovery, front matter, Markdown → HTML), `mdext`, `imaging`, `pdfpage`, `net` |
| `.claude/skills/<name>/` | One skill: `SKILL.md`, `scripts/`, `tests/`, optional `references/` and `assets/` |
| `.claude/agents/` | `pdf-reviewer`: reviews a built PDF through `make review` — checks, sheets, zooms — and returns only the defects |
| `.claude/hooks/` | Declared in `.claude/settings.json`: guard generated and immutable files, refuse the system Python, run `make brand` after `tokens.yaml`, run a skill's tests after its scripts change |
| `brand/tokens.yaml` | Single source of the art direction. Edit here, then `make brand`; `brand/tokens.css` is generated |
| `brand/icons/` | Lucide set, generated by `make icons`. Exclude it from searches: `grep --exclude-dir=icons` |
| `theme/` | The CSS cascade: `base`, `page`, `code`, one sheet per preset, and `epub.css` (not a preset) |
| `tests/` | The core's suite and the repository-level tests; each skill's suite lives in the skill |
| `docs/architecture.md` | Why each directory exists and where each skill stops |
| `out/` | Build outputs, gitignored |

A document is five directories, and the build reads one of them
(`docs/architecture.md` §11). `library/<topic…>/<slug>/` holds `document/`
(`index.md`, `cover.md`, `assets/` — the only one the build reads), `sources/`
(the user's: a tool may acquire into it, never derive into it, and never
modifies what is in it), `study/` (what the agent learned — extracted text,
provenance, an investigation's journal), `generators/` (code that draws an
asset) and `.work/` (regenerable, removed by `make clean`).

*The `document-anatomy` roadmap put the library into this shape in phases 1 to
3. Phase 4 adds the guard that keeps it true, and phase 5 the manual,
`docs/document.md`.*

## Commands

```bash
make setup                                    # venv, dependencies, editable install, brand
make new DOC=topic/slug [PRESET=report] [TITLE="…"]
make import SRC=x.pdf DOC=topic/slug TO=en    # external PDF → document
make fetch URL=https://… DOC=topic/slug       # web page → document
make build [DOC=topic/slug]                   # PDF; whole library without DOC
make review DOC=topic/slug [ZOOM="3 7"]       # checks + pages four to a sheet, for the look
make epub [DOC=topic/slug]                    # EPUB, `report` preset only
make preview [DOC=…] / make preview-style     # EPUB review sheets
make watch DOC=topic/slug
make brand / make icons / make list / make clean
make test
```

## Rules no skill owns

- Always run Python through `.venv/bin/python`, never the system `python3`.
- Never modify `diagram-design`: it is a plugin installed outside the repository
  and replaced on update. It reads the art direction through the profile
  `brand/sync.py` writes, selected by the `.diagram-design` marker — change that
  mechanism, never the plugin. The skills under `.claude/skills/` belong to this
  repository and are edited freely.
- Part of the suite reads documents the user keeps out of the repository. On a
  fresh clone those tests fail for want of files, not of assertions.
